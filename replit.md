# Masakhe - SMME Business Platform

## Overview
Masakhe is a digital platform designed to assist South African SMMEs with comprehensive business management. Its core purpose is to streamline business registration, establish a digital presence, ensure tax compliance, facilitate financial tracking, manage social media, and enhance customer engagement. The platform aims to empower SMMEs by providing essential tools within a single, integrated application, featuring a South African flag-inspired color palette for its UI.

## User Preferences
- Remote MySQL database on Xneelo (no SQLite, no paid Replit services)
- South African business context (Rand currency, SA tax/compliance)

## System Architecture
Masakhe utilizes a React 18 frontend with TypeScript and Vite, communicating with an Express.js backend using `mysql2/promise` for database interactions. The application is styled with Tailwind CSS and `shadcn/ui` components, employing React Router DOM for navigation, TanStack React Query for state management, and Recharts for data visualization. Authentication is managed via `express-session` and `express-mysql-session` with `bcryptjs`.

Key architectural features include:
- **Modular Design**: The system is organized into distinct modules for social media, billing, finance, and user management, each with dedicated API routes and logic.
- **Multi-tenancy**: The Social Media Hub supports a workspace system with roles (Owner, Admin, Editor, Viewer), enabling collaborative management for businesses.
- **Subscription & Billing via Adumo Online**: Three plans — Starter R599/mo, Pro R899/mo, Premium R1499/mo. No free trial; subscriptions activate immediately on payment. Payment processed via Adumo Online Virtual HPP (Hidden Form POST) for monthly debit order subscriptions. Checkout flow: user selects plan and fills subscriber details on BillingPage → `POST /api/billing/checkout-session` generates JWT token and returns Adumo form fields → hidden form POST submits to Adumo HPP → Adumo redirects back to `GET /api/billing/return-redirect` which verifies the response token, creates ACTIVE subscription, and redirects to `/dashboard/billing?payment=success|failed|error`. Background scheduler handles monthly renewal invoice creation. Feature gating restricts premium modules based on subscription status. Admin-granted trials (TRIAL status, 7-day) can be applied per client from the admin dashboard.
- **Registration Flow**: Registration (`/register`) is payment-free — 6 steps (Account, Business Status, Identity, Business Details, Contact & Location, Confirmation). After successful registration, users are redirected to `/onboarding`. Subscription is set up from the Billing section inside the dashboard portal.
- **Plan Upgrade/Downgrade**: `POST /api/billing/change-plan` endpoint allows switching between Starter and Pro plans. Cancels existing subscription, creates new Adumo checkout session for the target plan. Frontend: `ChangePlanSection` component in BillingPage shows upgrade/downgrade option with target plan details and Adumo debit order form. Merchant reference uses `UPG_` prefix for plan change invoices.
- **Trial Banner & Walkthrough**: `TrialBanner` component (in dashboard) shows a dismissible banner with days remaining and a modal popup on first login during trial; locks access modal when trial expires or subscription is past-due. `DashboardWalkthrough` component shows a guided tour card on first login, stepping through all dashboard sections.
- **Dynamic Dashboard**: The dashboard provides a real-time overview of business KPIs, financial data, and social media activity through dynamic charts and aggregated data.
- **Content Management**: Features a comprehensive Social Media Hub with a content calendar, post builder supporting multi-platform targeting, and a media library. A background worker handles scheduled post publishing with retry logic.
- **Custom Domain Hosting**: Users can connect their own domain (e.g. `www.mybusiness.co.za`) to their Masakhe-built website. The domain is saved in `websites.custom_domain`. The React app's `CustomDomainGate` component detects incoming requests on a custom domain (via `GET /api/websites/by-domain?hostname=...`), bypasses the main app shell, and renders the correct published site directly. Users are shown CNAME DNS instructions in the Website Builder sidebar. DB columns: `custom_domain VARCHAR(255) NULL UNIQUE`, `domain_verified TINYINT(1) DEFAULT 0`.
- **User & Business Profile Management**: Includes a settings page for managing user and business profiles, including logo uploads.
- **Website Builder**: A customizable website builder with **44 industry-specific templates** (41 standard + 3 premium). Templates defined in `src/components/website/templates.ts`, icons mapped in `src/pages/WebsiteBuilder.tsx`. Standard templates span: Professional Services, Restaurant, Retail, Beauty, Construction, Creative, Legal, Accounting, Real Estate, Healthcare, Education, Fitness, Automotive, Cleaning, IT/Technology, Agriculture, Transport, Events, Security, Travel, Consulting, Funeral, Bakery, Childcare, Solar, Printing, Staffing, Petcare, Church, Guesthouse, Fashion, Plumbing & HVAC, Photography & Videography, Catering & Corporate Events, Driving School, Pharmacy & Chemist, NGO & Non-Profit, Mining & Resources, Hair Salon & Barber, Insurance Broker, Home Improvement. Premium templates (Pro plan R2,500/month only, marked `premium: true` in `templateList`): **Car Showroom** (Porsche-inspired cinematic dark style, includes `vehicle_listings` section), **Financial Brokerage** (Oracle Brokers-inspired navy/gold, `heroStyle: "carousel"` auto-rotating slideshow), and **Luxury Estate Agency**. Premium gating: WebsiteBuilder checks `/api/billing/status`, shows Crown/Lock badges, blocks selection for non-pro users. **TemplatePicker UI**: Search bar (by name/industry), Sort (A→Z, Z→A, Default), and Category filter chips (Trade & Construction, Food & Hospitality, Health & Wellness, Professional Services, Finance & Legal, Creative & Media, Retail & Commerce, Technology, Property, Agriculture & Transport, Education & Community, Events, Premium). Category labels shown on each template card. Hero styles available: corporate, centered, bold, gradient, cinematic, minimal, carousel. Contact form section submits leads to `/api/leads/submit`.
- **Vehicle Inventory System** (Pro plan only): Car Showroom template users can manage vehicle listings from the dashboard. DB table: `vehicle_listings` (id, website_id, user_id VARCHAR(36), make, model, variant, year, price (cents), mileage, fuel_type, transmission, color, body_type, description, features JSON, images JSON, status, featured). API: `server/vehicles.ts` at `/api/vehicles` — public routes (`/public/by-website/:id`, `/public/detail/:id`) are defined before `requireAuth` middleware; authenticated CRUD routes enforce ownership (website `owner_id` validated on create, `user_id` checked on update/delete). Frontend: `VehicleManagementPage.tsx` fetches websites via `/api/websites/mine`. Published site: `VehicleListingsSection` in SectionRenderer fetches vehicles via `/api/vehicles/public/by-website/:id`. Vehicle detail page: `VehicleDetailPage.tsx` at `/site/:slug/vehicle/:vehicleId` with image gallery, specs, features, and lead capture contact form. Price stored in cents, displayed via `price/100`.
- **Website Leads System** (Pro plan only): Contact forms on vehicle detail pages and brokerage sites submit leads. DB table: `website_leads` (id, website_id, user_id VARCHAR(36), vehicle_id, name, email, phone, message, source, status, notes). API: `server/leads.ts` at `/api/leads` (public POST `/submit` — looks up `owner_id` from websites table; authenticated GET/PATCH/DELETE + stats + `GET /export` CSV download + `POST /import` CSV bulk upload). Frontend: `LeadsPage.tsx` with stats dashboard, search/filter, status management (new→contacted→qualified→converted→closed), vehicle badges, Import CSV button, Export CSV button.
- **Clients Management** (Brokerage CRM): Full client portfolio management for brokerages. DB tables: `broker_clients` (personal info, contact, employment, financial, brokerage profile — risk profile, credit score, policy number, property interest) and `broker_client_documents` (document uploads stored as base64 LONGTEXT, with document_type, file_size, mime_type). API: `server/clients.ts` at `/api/clients` — CRUD (GET/POST/PUT/DELETE), `GET /stats`, `GET /export` CSV, `POST /import` CSV, `GET/:id/documents`, `POST/:id/documents` (multipart), `DELETE/:id/documents/:docId`. Frontend: `ClientsPage.tsx` — side-by-side client list + detail panel, stats cards, search/filter, animated Add/Edit modal with 4 form sections (personal, contact, employment, brokerage), document upload panel with type selector, download and delete per document. Nav entry under `/dashboard/clients` with UserCheck icon.
- **Tenders**: Both admins and regular businesses can create tenders (with title, description, category, budget range, location, deadline, requirements). Users can browse open tenders, search/filter by category, view details, and submit applications with cover letters and proposed amounts. Tender owners can review applications and update their status (Pending → Shortlisted → Accepted/Rejected). Users cannot apply to their own tenders. Admins have full oversight of all tenders via the admin panel. DB tables: `tenders` and `tender_applications`. API: `server/tenders.ts` mounted at `/api/tenders` (user routes at `/user/*`, admin routes at `/admin/*`). Frontend: `src/pages/TendersPage.tsx` (user dashboard with browse/create/manage views), `AdminTenders` component in `AdminDashboard.tsx` (admin panel).
- **Business Funding Toolkit** (6 integrated modules, all in `server/documents.ts` + dedicated frontend pages):
  - **CIPC Company Verification** (`CompanyVerifyPage.tsx`, `/api/documents/companies`): Register company profiles with CIPC details (reg number, type, directors, address). "Verify Company" button marks is_verified=1 and shows green "Verified by CIPC" badge. Companies are reusable across all other toolkit modules. DB table: `companies`.
  - **Business Plan Builder** (`BusinessPlanPage.tsx`, `/api/documents/business-plans`): Expanded to 6-step AI-powered form (Business Overview + company selector, Market Analysis, Products & Services, Operations, Marketing, Financials). Generates 8-section professional plan via OpenAI. Auto-saves drafts. PDF export via window.print().
  - **Funding Proposal Generator** (`FundingProposalPage.tsx`, `/api/documents/funding-proposals`): 3-step form with company selector on step 1 (pre-fills business name). Generates 9-section proposal for SA programmes (SEFA/IDC/NEF/SEDA). PDF export.
  - **Annual Financial Statements** (`FinancialStatementsPage.tsx`, `/api/documents/financial-statements`): Form-based tool computing Income Statement, Balance Sheet, P&L. Recharts bar chart. PDF and CSV export.
  - **Funding Application Generator** (`FundingApplicationPage.tsx`, `/api/documents/funding-applications`): Select programme (SEFA/NEF/NYDA/IDC), link company + business plan + statements + proposal. AI auto-populates formal 10-section application from all linked data. PDF export. DB table: `funding_applications`.
  - **Funding Scoring** (`GrantReadinessPage.tsx`, `/api/documents/grant-readiness`): Scoring system (100 pts total): company verified (25), business plan (20), financial statements (20), funding proposal (15), funding application (10), tax number (5), business registered (5). Ring chart with colour coding (red/amber/green). Clickable next steps with point values. Manual checks for tax number and business registration stored via `/api/funding/readiness`.
- **Dashboard Toolkit Section**: DashboardOverview has a "Business Funding Toolkit" 6-card grid at the bottom. DashboardPage has nav items for "Verify Company" (Building2) and "Funding Applications" (Send), and routes for both new pages.
- **Notifications**: Real-time notification system with bell icon dropdown in the dashboard header. DB table: `notifications`. API: `server/notifications.ts` at `/api/notifications`. Notifications are auto-generated for tender applications (to tender owner) and application status changes (to applicant). Dropdown shows unread count badge, mark-as-read, mark-all-read, clickable links to relevant pages. Polls every 30s for updates. Frontend: `src/components/NotificationDropdown.tsx`.
- **Subscription Banner**: `TrialBanner` component shows a dismissible amber banner at the top of the dashboard when the user has no active subscription, prompting them to view plans. If TRIAL expired or PAST_DUE, shows a lock modal. Admin-granted TRIAL status shows days remaining.
- **Email System**: Sends branded HTML emails via SMTP (smtp.masakhegroup.co.za:465) using nodemailer with TLS. Includes welcome email on registration and password reset email flow. `APP_URL` env var set to `https://masakhegroup.co.za` (not replit.dev) to avoid Spamhaus blacklisting. Configured via `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_FROM`, `SMTP_SECURE`, `SMTP_PASSWORD` env vars. Implementation: `server/email.ts` (sendWelcomeEmail, sendPasswordResetEmail), called from `server/auth.ts` endpoints (fire-and-forget, non-blocking).
- **Password Reset Flow**: DB table `password_reset_tokens` (id, user_id, token VARCHAR(64), expires_at, used, created_at). Token expires in 1 hour, single-use, previous tokens invalidated on new request. Endpoints: `POST /api/auth/forgot-password` (always returns ok for security), `POST /api/auth/reset-password` (validates token, hashes new password). Frontend: `ForgotPasswordPage.tsx`, `ResetPasswordPage.tsx`. Login page has "Forgot your password?" link.
- **Leave & HR Module**: Full leave management at `/dashboard/leave`. Backend: `server/leave.ts` at `/api/leave`. DB tables: `leave_requests` (id, user_id, employee_id, leave_type ENUM[Annual,Sick,Family Responsibility,Unpaid], start_date, end_date, working_days, reason, status ENUM[pending/approved/rejected], approved_by, notes) and `leave_balances` (id, user_id, employee_id, year, leave_type, total_days, used_days, pending_days). Migrations run on startup via `runLeaveMigrations()`. Frontend: 3 tabs — Overview (balance bars per employee per type), Requests (list with approve/reject dialogs), New Request (form with working-day calculation). Reuses the `employees` table from payroll. Default allocations: Annual 15d, Sick 30d, Family Responsibility 3d, Unpaid unlimited. Groupd under "HR & Payroll" in the sidebar with Payroll.
- **Payroll Module**: Full SA payroll management at `/dashboard/payroll`. Backend: `server/payroll.ts` at `/api/payroll`. DB tables: `employees` (id, user_id, first/last name, SA ID, tax number, position, department, employment type, basic_salary_cents, age, uif_exempt, bank details, status) and `payroll_runs` (per-run snapshot with all calculated figures). PAYE uses SARS 2025/2026 tax brackets + primary/secondary/tertiary rebates. UIF is 1% employee + 1% employer capped at R177.12/month. Features: employee CRUD, live calculation preview, allowances (travel, housing, overtime, bonus) and deductions (pension, medical, loans), payslip generation + print with company logo/details, payslip history. Quick-run button from employee list.
- **Admin Impersonation**: Admins can log in as any non-admin user from the admin Clients page. Clicking the login icon (LogIn) beside a user triggers `POST /api/admin/impersonate/:userId`, which stores `originalAdminId` in the session and switches `userId` to the target. A persistent amber banner appears in the dashboard showing who is being impersonated and a "Return to Admin Account" button which calls `POST /api/auth/impersonate/end` to restore the admin session. Admins cannot impersonate other admins. The `SessionData` interface (in `server/auth.ts`) includes `originalAdminId?: string`. `GET /api/auth/me` returns `isImpersonating` and `originalAdminName` fields. Frontend state is managed via `AuthContext` with `isImpersonating`, `originalAdminName`, and `stopImpersonating()`.
- **Data Security**: Employs AES-256-GCM encryption for sensitive data like social account tokens.
- **PDF Generation**: Uses `pdf-lib` for server-side generation of invoices and terms PDFs.

## Adumo Online Integration
- **Files**: `server/adumo.ts` (JWT generation/verification), `server/billing.ts` (checkout-session + return-redirect endpoints)
- **Secrets**: `ADUMO_CUID` (MerchantID), `ADUMO_AUID` (ApplicationID), `ADUMO_JWT_SECRET`, `ADUMO_ENV` (staging/production), `APP_URL`
- **JWT Token**: HS256 signed, contains `iss`, `cuid`, `auid`, `amount`, `mref`, `jti`, `iat` (now-60s), `exp` (now+600s)
- **Form Fields**: puid, MerchantID, ApplicationID, MerchantReference, Amount, Token, txtCurrencyCode (ZAR), RedirectSuccessfulURL/RedirectFailedURL, subscription fields (frequency=MONTHLY, collectionDay, startDate, endDate, collectionValue, accountNumber, contactNumber, mobileNumber, emailAddress)
- **Return Flow**: Adumo redirects to `GET /api/billing/return-redirect?status=success&merchantRef=SUB_xxx`. Server verifies `_RESPONSE_TOKEN` JWT (validates mref + amount match), marks invoice PAID, creates ACTIVE subscription immediately, extracts card details if available, then redirects to `/dashboard/billing?payment=success`
- **Security**: Response token verification validates merchant reference and amount match before accepting payment. Invoice uses stored `plan_id` for subscription creation (not amount-based lookup). T&C acceptance checkbox required before form submission.

## Reseller / Partner Program
- **Backend**: `server/reseller.ts` — DB tables: `resellers`, `reseller_clients`, `reseller_commissions`. Column `referred_by` added to `users` by auth.ts at registration. `app.use("/api/reseller", resellerRouter)` wired in `server/index.ts`.
- **7-Rank System**: Starter (S1) → Builder (B2) → Leader (L3) → Manager (M4) → Director (D5) → Executive (E6) → Diamond Elite (DE7). Rank auto-computed on each `/me` call from client count.
- **Commission Rates**: Direct L1=20%, L2=10%, L3=5%, L4=3%, L5=3%. Binary bonus=10% weaker leg (capped). One-off rank bonuses: R500 → R50,000.
- **Key Endpoints**: `GET /api/reseller/check/:code` (public — validates referral code), `POST /api/reseller/apply`, `GET /api/reseller/me`, `GET /api/reseller/me/clients`, `GET /api/reseller/me/commissions`, `GET /api/reseller/leaderboard`, `POST /api/reseller/me/invite` (send invite email), admin routes.
- **Registration**: `auth.ts` POST `/api/auth/register` accepts `referralCode`, stores in `referred_by`, calls `linkResellerClient`. When `businessStatus === "reseller"`, auto-creates an active reseller record (`autoRegisterReseller`). `RegisterPage.tsx` reads `?ref=` from URL via `useSearchParams`, validates via `/api/reseller/check/:code`, shows green referrer banner if valid, passes `referralCode` to register call. Selecting "Reseller Partner" on step 2 skips steps 3-5 (Identity, Business Details, Contact) and jumps to confirmation with partner-specific summary. After submit, redirects to `/partner`.
- **Separate Partner Portal**: `src/pages/ResellerPortal.tsx` — standalone portal with dark sidebar (Masakhe logo, user card, nav: Overview/My Clients/Commissions/Ranks & Tiers/Leaderboard, Sign Out). Route: `/partner`. Controls `activeTab` state passed to `ResellerDashboard` (which hides its own tab bar when controlled by the portal). Resellers are redirected to `/partner` on login (`LoginPage.tsx` checks `result.isReseller`). `DashboardPage.tsx` redirects resellers away via `useEffect` + `navigate`. `is_reseller` flag included in login and `/me` responses via LEFT JOIN on `resellers` table.
- **SMME Dashboard**: `src/pages/ResellerDashboard.tsx` still embedded in SMME dashboard at `/dashboard/reseller` as "Partner Program" tab (for SMME users who also want to join the program). Tab bar hidden when rendered inside the portal.

## External Dependencies
- **Database**: Remote MySQL hosted on Xneelo (`sql16.cpt3.host-h.net`).
- **Payment Gateway**: Adumo Online (Virtual HPP form POST for debit order subscriptions).
- **Social Media APIs**: Meta (Facebook/Instagram) with full OAuth connection and real Graph API publishing via `server/social/meta-oauth.ts`. LinkedIn, X, TikTok, YouTube remain in Mock Mode. Meta OAuth flow: start → redirect to Facebook → callback at `/api/social/oauth/meta/callback` → exchanges code for long-lived token → fetches user's Pages + Instagram business accounts → stores encrypted page access tokens. Publishing: `publishToFacebook` posts to `/{page-id}/feed`, `publishToInstagram` uses container-based publishing (`/{ig-user-id}/media` → poll status → `/{ig-user-id}/media_publish`). Instagram requires an image. Secrets: `META_APP_ID`, `META_APP_SECRET`. Redirect URI must be registered in Meta developer portal: `{APP_URL}/api/social/oauth/meta/callback`.
- **Session Management**: `express-mysql-session` for storing session data in MySQL.
- **PDF Generation**: `pdf-lib` for creating PDF documents.
- **File Uploads**: `multer` for handling media file uploads.
- **CSV Import/Export**: Finance ledger entries and invoices support CSV export (download) and CSV import (upload). Finance export: Date, Type, Category, Amount (Rands), Description. Invoice export: Invoice Number, Customer Name, Customer Email, Items (semicolon-separated), Total, Status, Date. Import endpoints accept CSV uploads via multer, validate rows, and insert records. Server: `GET/POST /api/finance/export|import`, `GET/POST /api/invoices/export|import`. Frontend: Export/Import CSV buttons on FinancePage and InvoicesPage.
