# Masakhe - SMME Business Platform

## Overview
Masakhe is a digital platform designed to assist South African SMMEs with comprehensive business management. Its core purpose is to streamline business registration, establish a digital presence, ensure tax compliance, facilitate financial tracking, manage social media, and enhance customer engagement. The platform aims to empower SMMEs by providing essential tools within a single, integrated application, featuring a South African flag-inspired color palette for its UI.

## User Preferences
- Remote MySQL database on Xneelo (no SQLite, no paid Replit services)
- South African business context (Rand currency, SA tax/compliance)

## System Architecture
Masakhe utilizes a React 18 frontend with TypeScript and Vite, communicating with an Express.js backend using `mysql2/promise` for database interactions. The application is styled with Tailwind CSS and `shadcn/ui` components, employing React Router DOM for navigation, TanStack React Query for state management, and Recharts for data visualization. Authentication is managed via `express-session` and `express-mysql-session` with `bcryptjs`.

Key architectural features include:
- **Modular Design**: The system is organized into distinct modules for social media, billing, finance, and user management, each with dedicated API routes and logic.
- **Multi-tenancy**: The Social Media Hub supports a workspace system with roles (Owner, Admin, Editor, Viewer), enabling collaborative management for businesses.
- **Subscription & Billing via Adumo Online**: Three branded plans — **Enterprize** (starter) R599/mo, **Enterprize Plus** (pro) R899/mo, **Enterprize Premium** (premium) R1499/mo. Plan codes remain `starter`/`pro`/`premium` internally. Plan benefits: Enterprize = Overview + Website + Social Media Hub + Biz Connect + WhatsApp Support Portal (single user). Enterprize Plus adds Financial Transactions (Income/Expenses, Quotes/Invoices), Manage Leads & Clients, Manage Campaigns, Priority Support. Enterprize Premium adds Multi-user dashboard (up to 4 users, permission based), Manage Employees, Manage Payroll, all future updates free, Premium Support. Plan listings live in `src/pages/PricingPage.tsx`, `src/pages/BillingPage.tsx` (`planOptions`), `src/pages/LandingPage.tsx` (`pricingPlans`). DB seed in `server/db.ts` updates plan names on every boot. Payment processed via Adumo Online Virtual HPP (Hidden Form POST) for monthly debit order subscriptions. Background scheduler handles monthly renewal invoice creation. Feature gating restricts premium modules based on subscription status. Admin-granted trials (TRIAL status, 7-day) can be applied per client from the admin dashboard.
- **Plan-tier feature gating in dashboard sidebar** (`src/pages/DashboardPage.tsx`): Each `NavItem` and `NavChild` may declare `requiresPlan: "pro" | "premium"`. The dashboard reads `/api/billing/status` (returns `plan` code) and converts it via `PLAN_TIER` (starter=1, pro=2, premium=3). Items the user's plan doesn't meet render as muted with a small amber "Plus" or "Premium" crown badge and link to `/dashboard/billing` instead of the actual route. Admins always get `premium` tier. Locked nav items currently: Transactions group + children (pro), Clients (pro), Campaigns (pro), HR & Payroll group + children (premium), Team Members (premium).
- **Registration Flow**: Registration (`/register`) is payment-free — 6 steps (Account, Business Status, Identity, Business Details, Contact & Location, Confirmation). After successful registration, users are redirected to `/dashboard/billing` where they pick a plan to start their free trial (the trial is no longer auto-created at registration). Subscription is set up from the Billing section inside the dashboard portal.
- **Plan-based Free Trial**: New users land on `/dashboard/billing` and see a `TrialPickerSection` (3 plan cards). Clicking "Start my 14-day free trial of {plan}" calls `POST /api/billing/start-trial` with `{ planCode }`, which creates a `billing_subscriptions` row with `status='TRIAL'`, `plan_id` set to the chosen plan, and `trial_end_at` 14 days out (30 days for resellers). Until the trial is started, `/api/billing/access-status` returns `blocked: true, subscriptionStatus: "NONE"` so `ProtectedRoute` keeps the user on `/dashboard/billing`. Once the trial expires (`trial_end_at < now`), `access-status` returns `blocked: true, subscriptionStatus: "TRIAL"` and the BillingPage shows a "Free trial ended — subscribe to continue" panel containing the existing `SubscribeTabSection` (manual pay or debit-order tabs). During an active trial, the BillingPage shows the trial end date plus the same `SubscribeTabSection` so users can convert early.
- **Plan Upgrade/Downgrade**: `POST /api/billing/change-plan` endpoint allows switching between Starter and Pro plans. Cancels existing subscription, creates new Adumo checkout session for the target plan. Frontend: `ChangePlanSection` component in BillingPage shows upgrade/downgrade option with target plan details and Adumo debit order form. Merchant reference uses `UPG_` prefix for plan change invoices.
- **Trial Banner & Walkthrough**: `TrialBanner` component (in dashboard) shows a dismissible banner with days remaining and a modal popup on first login during trial; locks access modal when trial expires or subscription is past-due. `DashboardWalkthrough` component shows a guided tour card on first login, stepping through all dashboard sections.
- **Dynamic Dashboard**: The dashboard provides a real-time overview of business KPIs, financial data, and social media activity through dynamic charts and aggregated data.
- **Content Management**: Features a comprehensive Social Media Hub with a content calendar, post builder supporting multi-platform targeting, and a media library. A background worker handles scheduled post publishing with retry logic.
- **Custom Domain Hosting**: Users can connect their own domain (e.g. `www.mybusiness.co.za`) to their Masakhe-built website. The domain is saved in `websites.custom_domain`. The React app's `CustomDomainGate` component detects incoming requests on a custom domain (via `GET /api/websites/by-domain?hostname=...`), bypasses the main app shell, and renders the correct published site directly. Users are shown CNAME DNS instructions in the Website Builder sidebar. DB columns: `custom_domain VARCHAR(255) NULL UNIQUE`, `domain_verified TINYINT(1) DEFAULT 0`.
- **User & Business Profile Management**: Includes a settings page for managing user and business profiles, including logo uploads.

Templates defined in `src/components/website/templates.ts`, icons mapped in `src/pages/WebsiteBuilder.tsx`. ## Adumo Online Integration
- **Files**: `server/adumo.ts` (JWT generation/verification), `server/billing.ts` (checkout-session + return-redirect endpoints)
- **Secrets**: `ADUMO_CUID` (MerchantID), `ADUMO_AUID` (ApplicationID), `ADUMO_JWT_SECRET`, `ADUMO_ENV` (staging/production), `APP_URL`
- **JWT Token**: HS256 signed, contains `iss`, `cuid`, `auid`, `amount`, `mref`, `jti`, `iat` (now-60s), `exp` (now+600s)
- **Form Fields**: puid, MerchantID, ApplicationID, MerchantReference, Amount, Token, txtCurrencyCode (ZAR), RedirectSuccessfulURL/RedirectFailedURL, subscription fields (frequency=MONTHLY, collectionDay, startDate, endDate, collectionValue, accountNumber, contactNumber, mobileNumber, emailAddress)
- **Return Flow**: Adumo redirects to `GET /api/billing/return-redirect?status=success&merchantRef=SUB_xxx`. Server verifies `_RESPONSE_TOKEN` JWT (validates mref + amount match), marks invoice PAID, creates ACTIVE subscription immediately, extracts card details if available, then redirects to `/dashboard/billing?payment=success`
- **Security**: Response token verification validates merchant reference and amount match before accepting payment. Invoice uses stored `plan_id` for subscription creation (not amount-based lookup). T&C acceptance checkbox required before form submission.

## Reseller / Partner Program
- **Backend**: `server/reseller.ts` — DB tables: `resellers`, `reseller_clients`, `reseller_commissions`. Column `referred_by` added to `users` by auth.ts at registration. `app.use("/api/reseller", resellerRouter)` wired in `server/index.ts`.
- **7-Rank System**: Starter (S1) → Builder (B2) → Leader (L3) → Manager (M4) → Director (D5) → Executive (E6) → Diamond Elite (DE7). Rank auto-computed on each `/me` call from client count.
- **Commission Rates**: Direct L1=20%, L2=10%, L3=5%, L4=3%, L5=3%. Binary bonus=10% weaker leg (capped). One-off rank bonuses: R500 → R50,000.
- **Key Endpoints**: `GET /api/reseller/check/:code` (public — validates referral code), `POST /api/reseller/apply`, `GET /api/reseller/me`, `GET /api/reseller/me/clients`, `GET /api/reseller/me/commissions`, `GET /api/reseller/leaderboard`, `POST /api/reseller/me/invite` (send invite email), admin routes.
- **Registration**: `auth.ts` POST `/api/auth/register` accepts `referralCode`, stores in `referred_by`, calls `linkResellerClient`. When `businessStatus === "reseller"`, auto-creates an active reseller record (`autoRegisterReseller`). `RegisterPage.tsx` reads `?ref=` from URL via `useSearchParams`, validates via `/api/reseller/check/:code`, shows green referrer banner if valid, passes `referralCode` to register call. Selecting "Reseller Partner" on step 2 skips steps 3-5 (Identity, Business Details, Contact) and jumps to confirmation with partner-specific summary. After submit, redirects to `/partner`.
- **Separate Partner Portal**: `src/pages/ResellerPortal.tsx` — standalone portal with dark sidebar (Masakhe logo, user card, nav: Overview/My Clients/Commissions/Ranks & Tiers/Leaderboard, Sign Out). Route: `/partner`. Controls `activeTab` state passed to `ResellerDashboard` (which hides its own tab bar when controlled by the portal). Resellers are redirected to `/partner` on login (`LoginPage.tsx` checks `result.isReseller`). `DashboardPage.tsx` redirects resellers away via `useEffect` + `navigate`. `is_reseller` flag included in login and `/me` responses via LEFT JOIN on `resellers` table.
- **SMME Dashboard**: `src/pages/ResellerDashboard.tsx` still embedded in SMME dashboard at `/dashboard/reseller` as "Partner Program" tab (for SMME users who also want to join the program). Tab bar hidden when rendered inside the portal.

## Automations (Money-In + CRM, 9 automations)
- **Files**: `server/automations.ts` (settings GET/PUT, recurring CRUD, activity log, send hooks: `sendThankYouReceipt`, `sendLeadAutoreply`, `checkStopCreditAndAlert`), `server/automations-scheduler.ts` (master loop runs every 30 min: recurring invoices, quote follow-ups + expiry, late fees, lead drip, inactive nudge, birthday + anniversary), `src/pages/AutomationsPage.tsx` (single page with collapsible sections per automation, recurring invoice form modal, activity log).
- **Wired**: `server/index.ts` registers `automationsRouter` at `/api/automations` and calls `startAutomationsScheduler()` alongside other schedulers. `server/leads.ts` POST `/submit` fires `sendLeadAutoreply()` non-blocking. `server/invoices.ts` POST `/` fires `checkStopCreditAndAlert()` non-blocking on invoice (not quote). New invoice endpoints: `POST /api/invoices/:id/mark-paid` (sets status='paid', paid_at, fires thank-you receipt), `POST /api/invoices/:id/mark-unpaid` (reverses).
- **Schema additions** (in `server/db.ts`):
  - `invoices`: paid_at, recurring_id, valid_until, quote_followups_sent, last_quote_followup_at, quote_expiry_notified_at, late_fee_cents, late_fee_applied_at, thank_you_sent_at
  - `broker_clients`: client_since, company_anniversary, last_contacted_at, inactive_nudge_sent_at, last_birthday_msg_year, last_anniversary_msg_year
  - `website_leads`: autoreply_sent_at, drip_step, drip_last_sent_at, drip_completed
  - New tables: `automation_settings` (one row per user, all 9 automation toggles + templates), `recurring_invoices` (template-driven, frequency: weekly/monthly/quarterly/yearly/custom_days, with auto_send), `automation_log` (audit trail).
- **Templating**: All emails use `{{token}}` substitution via `renderTemplate()`. Common tokens: `{{customer_name}}`, `{{lead_name}}`, `{{amount}}`, `{{invoice_number}}`, `{{quote_date}}`, `{{business_name}}`. Email rendering uses `wrapEmail()` for branded HTML wrapper.
- **UI**: `Automations` nav item (Sparkles icon, label "Automations") added at `/dashboard/automations` between Campaigns and HR & Payroll, requires `pro` plan. Mark-Paid button + status pill (Paid/Outstanding) added to InvoicesPage row; late-fee shown in total when applied.
- **Defaults**: All automations OFF by default except `thank_you_enabled`, `quote_followup_enabled`, and `lead_autoreply_enabled` (which start ON since they're low-risk reactive sends, not unsolicited campaigns). Drip emails come pre-seeded with 3 sensible South African-flavoured templates.
